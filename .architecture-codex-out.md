#### 1. Product in one paragraph

DigitalBrain ships as `DigitalBrain.Host`: a durable Orleans brain with a selected set of trusted domain modules and a deliberately small SDK. An owner sends and observes durable facts, asks Creator to turn intent into one reviewable C# file, approves that exact artifact, and receives its effect only after a cold restart admits it. A module author owns a domain namespace such as `DigitalBrain.Chart`, writes a trusted `ChartNeuron : Neuron` with exact handlers and any genuinely needed typed capabilities, and supplies one module manifest; generated candidates write ordinary constrained `Neuron` classes but can only fire granted synapses into trusted modules.

#### 2. Core laws (max 8 bullets)

- A `Synapse` is an immutable fact with no reply; handling is exact `IHandle<T>`, never base-type subscription or catch-all dispatch.
- Replies exist only on registered typed capability interfaces in trusted code paths. Retire `RequestSynapse<T>` after its callers migrate to capabilities or journal/projection observation.
- One durable turn exists: deliver → handle → journal/state/outbox commit → drain. Candidates never get a second journal, state store, or outbox.
- Core alone owns owner identity, causation, delivery/effect IDs, envelopes, and journal projection. Journals contain causal facts, never prompts or secrets.
- Trusted modules derive from `DigitalBrain.Core.Trusted.Neuron`; candidates derive from the closed `DigitalBrain.Candidate.Neuron` profile and run only inside `CandidateActivationGrain`.
- Candidate code never sees `IServiceProvider`, `GrainFactory`, raw Orleans types, timers, or trusted capability proxies. Every `FireSynapse` is grant-checked; trusted effects check again.
- Routes are immutable at cold boot from verified active candidates; every generated-targeted delivery pins its revision. No hot admission, mutable subscriptions, or interpreter path.
- Authoring is intent → Creator-owned AST → one fixed C# file → policy/build/quarantine → owner approval → signed pointer → quiesced cold activation. Rollback advances a new pointer; it never restores mutable source.

#### 5. What dies from current tree

- `DigitalBrain.Kernel/` as a name: rename it to `DigitalBrain.Host/`.
- `DigitalBrain.Scripting/`: delete it once `DigitalBrain.Authoring` proves reviewed one-file creation and cold admission. It is a temporary-project `dotnet run` probe, not authoring.
- `src/modules/sdk/DigitalBrain.Modules.Sdk/`: delete the package and namespace. Move active southbound MCP work to `modules/integrations/mcp/`; delete the webhook lane now—its only observed consumer is the Kernel catalog.
- `src/core/kernel/DigitalBrain.Client/`, `src/core/aspire/*`, and `src/core/security/DigitalBrain.Security/` as locations/layers: move Client and Aspire to SDK; fold protection into Core.
- Public grain plumbing in Abstractions: `INeuron`, `ISessionNeuron`, `IDigitalBrainNeuron`, `IJournalObserver`, `NeuronId.ToGrainId`, and `DigitalBrainResourceNames`. Keep any necessary grain protocol Core-internal.
- `ICompiledModule` plus manual `CapabilityManifest` and overlapping reflection catalogs: replace with one generated `ModuleManifest` consumed by Core composition.
- `RequestSynapse<TResponse>`, `Neuron.Replies`, correlated journal-polling replies, and public-but-hidden `GetGrainProxy`. Delete only after Chat, Google, Memory, Tasks, and Introspection have migrated.
- Product-side copies of POC `RunStore`, `JournalStore`, and `RunDocument`: never port them. The isolated POC may retain them until the product vertical supersedes its proof.
- Stale Behavior Studio residue: `clients/flutter/core/lib/src/behavior_*`, `sse_behavior_frames.dart`, `clients/flutter/shell/lib/behaviors/`, and their tests/seed tool.

#### 6. Strongest objection to your tree + defense

Two different `Neuron` bases look like the dual model you are trying to remove. They are actually the irreducible host-ABI distinction: trusted `Core.Trusted.Neuron` has grain and capability authority, while `Candidate.Neuron` has only state plus `FireSynapse`. Reusing the trusted base would hand generated code `ServiceProvider` and `GrainFactory`; collapsing trusted modules onto the candidate ABI would destroy capabilities. The package fence makes the illegal reference impossible, while generated source still says `: Neuron`—not `ScriptedNeuron`, not an interpreter.

#### 7. Minimal first vertical after this structure exists

Use one trusted `Chart` module and a test-only trusted `SocialPostObserved` ingress:

```text
owner intent
  → Creator emits one elon-chart.cs
  → validate, SDK-build, quarantine, approve
  → DigitalBrain.Host cold-starts verified candidate
  → SocialPostObserved("elonmusk")
  → generated RuleNeuron
  → generated ElonPostMatched
  → generated ChartForwarderNeuron
  → trusted AddChartPoint
  → trusted ChartNeuron projection + causal journal
```

The same artifact must survive one further cold restart and preserve exactly one chart point for the original delivery. That proves the merge seam without shipping a social product, a second journal, or generalized authoring.
