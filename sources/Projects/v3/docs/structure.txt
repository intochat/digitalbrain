## 2. Core Concepts: Neurons & Synapses

The entire system runtime space is modeled as a biological network:
*   **Neuron**: An Orleans grain representing an isolated, addressable logical actor. Each neuron is identified by a unique, brain-qualified grain key: `{BrainId}::{NeuronFqn}`.
*   **Synapse**: A strongly-typed data contract. It is represented as a C# `record` with metadata headers (e.g., `CorrelationId`, `CausationId`, `OriginBrain`, `DestinationBrain`).
*   **Routing**: Point-to-point via `ask <alias> to "<intent>"` or broadcast via `emit <Synapse>`.

## 3. Software 1.0 vs Software 2.0 Interoperability

We separate core platform capabilities from runtime-authored behaviors:

```
┌────────────────────────────────────────────────────────────────────────────┐
│                         SOFTWARE 2.0 (Authoring)                           │
│  Declarative .ino files written by Ino (LLM) or a Business Analyst.         │
│  Contains high-level logic, state declarations, UI layouts, and tests.     │
├────────────────────────────────────────────────────────────────────────────┤
│                                     │                                      │
│                           Interpreted / Transpiled                         │
│                                     ▼                                      │
├────────────────────────────────────────────────────────────────────────────┤
│                          SOFTWARE 1.0 (The Substrate)                      │
│  Statically typed C# code inside the SDK (DigitalBrain.SDK) or NuGet.     │
│  Handles files, OAuth, processes, Stripe, and vector search.               │
└────────────────────────────────────────────────────────────────────────────┘
```

*   **Software 1.0 (Core / SDK)**: Written in C#. Hand-crafted sidecars, connectors to hardware, AI libraries (`Microsoft.Extensions.AI`), and complex local services.
*   **Software 2.0 (Authored Units)**: Declared in `.ino` files. Compiled dynamically using Roslyn at runtime, verified via scenario blocks, and activated as dynamic grains.
*   **Interoperability (The Sidecar Pattern)**:
    An `.ino` file declares a handler as a `delegate` (Software 2.0). The co-located partial C# class implements the method (Software 1.0). The runtime links the two into a single dynamic assembly.

## 4. The Neuron Interface: Core vs Private Tools

A neuron is not an opaque block; it exposes its entire schema, telemetry, and capabilities via a structured **Definition Card** in the RFW UI.

```
┌───────────────────────────────────────────────────────────────────────┐
│ ● Acme.Insurance.Triage                                               │
├───────────────────────────────────────────────────────────────────────┤
│                                                                       │
│  [ Core Interface ]                       [ Private Tools ]           │
│                                                                       │
│  ┌─────────────────────────────┐         ┌─────────────────────────┐  │
│  │ State: incoming/outgoing    │         │ Triage(Claim)           │  │
│  │ Telemetry: metrics/logs     │         │                         │  │
│  └─────────────────────────────┘         │ [ Execute: SendSynapse] │  │
│                                          └─────────────────────────┘  │
│  ┌─────────────────────────────┐                                      │
│  │ Schema: Request/Response    │                                      │
│  └─────────────────────────────┘                                      │
│                                                                       │
└───────────────────────────────────────────────────────────────────────┘
```

### Core Interface Tools (Inherited)
Every neuron inherits a standardized core API from the substrate, exposing:
*   `tool.GetState()`: Returns the neuron's active journal logs and persistent variables.
*   `tool.GetTelemetry()`: Emits OpenTelemetry metrics (counters, histograms) and structured logs.
*   `tool.GetSchema()`: Outputs the exact schemas of the synapses it receives and emits.

### Private Tools (Functional Handlers)
A neuron defines specific handlers (`on SynapseName:`) mapping directly to executable operations:
*   These are represented in the developer/analyst UI as action cards with input fields matching the synapse parameters.
*   Clicking **Execute** fires a `SendSynapse` call under the hood, injecting the message directly into the grain's mailbox.

### 1. Free Domains (GitHub)
*   **Source**: Public GitHub repositories tagged with the topic `digitalbrain-domain`.
*   **Installation**: Performed via a simple `git clone --depth=1` to the brain's LocalAppData folder (`brains/{id}/domains/<owner>/<repo>`).
*   **Registry**: Implicit. The local directory structure represents the installed domain catalog.

### 2. Premium Bundles (`.bdom` / Marketplace)
*   **Format**: A signed ZIP file containing `manifest.json`, compiled `.ino` source files, and a publisher cryptographic signature (`signature.dat`).
*   **Front-matter Terms**: Commercial terms are declared directly inside the `.ino` header:
    ```ino

    # @license: commercial-eula
    # @requires: DigitalBrain.Ai.Chat >= 1.2
    neuron Acme.Enterprise.Billing
    ```
*   **Stripe checkout**: Standard Stripe session verifies payment, after which `LicenseNeuron` issues a signed, cryptographically secure offline license token.
*   **Install Gate**: The `LocalBundleInstaller` verifies (1) the code signature against the Marketplace public key, (2) the license token validity, (3) that all `@requires` dependencies resolve in the catalog, and (4) that all scenario tests run green.

## 7. Technical Challenges & Runtime Generation

The biggest engineering hurdles lie in generating, testing, and running new code on-demand at runtime.

### Challenge 1: The Compile-Simulate-Gate Loop
*   **Durable Tasks (Accede Pattern)**: When Ino receives a request to create a new behavior, the process runs inside an Orleans `DurableGrain` task. The state of the task is written to the journal at each transition (`Prompting` → `Compiling` → `Simulating` → `Activating`). If the silo crashes mid-generation, it resumes exactly where it left off.
*   **In-Memory Compilation**:
    1. Lex and parse the authored `.ino` file to an AST.
    2. Lower to a C# class string and generate the scenario test harness.
    3. Roslyn compiles the source in-memory, loading it via a dynamic `AssemblyLoadContext`.
    4. Execute the scenario block on the test runner.
    5. On success (green), hot-activate the neuron as an Orleans grain in the silo.

### Challenge 2: Built-in LLM serving
Neurons can leverage local models (like `nemotron-mini` for fast persona turns and `phi4` for strict JSON generation) served locally by Ollama or NIM containers. These containers are registered as Aspire resources and reference GPU passthrough arguments (`--gpus all` via `WithContainerRuntimeArgs`). Keyed `IChatClient` instances are injected directly into the neuron constructors by the runtime.

## 8. Open Source UI Neuron Kit

Instead of defining UI as raw, non-composable Flutter code, we propose that standard interactive UI components be exposed **as specialized neurons** with pre-defined RFW layouts and synapses:

### The Core Widget Neurons
1.  **`Button` : neuron**
    *   *Synapse*: `TapEvent` (emitted on click).
    *   *Usage*: Triggers behaviors when pressed. Can be wired to other neurons via target synapse bindings.
2.  **`Globe` : neuron**
    *   *Synapse*: `CoordinateSelected(lat: double, lng: double)`, `UpdateCenter(lat: double, lng: double)`.
    *   *Usage*: Surrounding glass card displaying geographical datasets or mapping coordinate flows dynamically.
3.  **`Cloak` : neuron**
    *   *Synapse*: `EncryptData(payload: text)`, `DecryptData(token: text)`.
    *   *Usage*: Intercepts and wraps state storage paths with local DPAPI/keychain encryption, shielding private properties from the LLM or external callers.
4.  **`Calendar` : neuron**
    *   *Synapse*: `DateSelected(date)`, `ScheduleEvent(title: text, start: datetime, end: datetime)`.
    *   *Usage*: Displays scheduler views and binds to Google Calendar/Outlook SDK sidecars.
5.  **`Layout` : neuron**
    *   *Synapse*: `StateChanged(neuronFqn: text, payload: json)`.
    *   *Usage*: Listens to state synapses in the canvas and automatically triggers re-flowing or resizing of card decks to ensure responsive layouts dynamically.
