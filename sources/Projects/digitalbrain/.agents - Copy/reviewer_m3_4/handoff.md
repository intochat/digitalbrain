## 2. Logic Chain

- **A. Escaping Robustness**:
  - *Premise*: C# normal string literals (like `"..."`) interpret backslashes (like `\` or `\t`) as escape characters, leading to compiler error `CS1009` when scenario names or file paths contain unescaped backslashes.
  - *Observation*: The hotfix leverages C# verbatim string literals (`@""`) in the generated output, e.g. `@"{escapedName}"` and `@"{escapedDisplayName}"`.
  - *Deduction*: By using `@`, the C# compiler treats backslashes literally rather than interpreting them as escape sequences. Inside verbatim literals, double quotes must be escaped by doubling them (`""`), which the generator handles correctly via `.Replace("\"", "\"\"")`. This prevents all syntax compilation issues.

- **B. Duplicate Scenario Suffixing**:
  - *Premise*: When a `.ino` file contains duplicate scenario names, generating tests with the exact same display name causes collisions/collapsing. The runtime test adapter in `InoScenarioProjection.cs` appends ` [#{i}]` suffixes to resolve duplicates.
  - *Observation*: The generator groups scenarios by name, identifies duplicates, and appends ` [#{i}]` to the display name matching the duplicates.
  - *Deduction*: The generated C# facts match the exact runtime display name labels generated by the adapter. The dispatch key is passed correctly as `"scenario:{i}"` (index-based), allowing the runner to distinguish scenarios by index rather than name, preserving execution integrity.

- **C. Null Directory Guard**:
  - *Premise*: `Path.GetDirectoryName` can return `null` if the input path has no directory component or points to a root folder, leading to a `NullReferenceException` when `.Replace("\\", "/")` is called.
  - *Observation*: The hotfix evaluates `dir is null ? "" : dir.Replace("\\", "/")`.
  - *Deduction*: If `dir` is null, `rootDir` defaults safely to `""`. When combined with file paths later during `Path.GetFullPath(Path.Combine(rootDir, fileName))`, it successfully resolves using the relative current working directory, preventing any null pointer crash.

- **D. .NET Standard 2.0 Compatibility**:
  - *Premise*: The source generator assembly targets `.NET Standard 2.0`. LINQ's `.ToHashSet()` is not available natively in .NET Standard 2.0 without additional assembly dependencies or polyfills.
  - *Observation*: The hotfix initializes the duplicate names set using `new HashSet<string>(..., StringComparer.Ordinal)`.
  - *Deduction*: This constructor is fully supported in `.NET Standard 2.0` and standard .NET runtimes, ensuring cross-platform compile compatibility without third-party dependencies.

## 3. Caveats

- **Filesystem Constraints on File Names**:
  - While scenario names and display names are perfectly escaped against double-quotes (using double double-quotes `""`), the `fileName` in the generated string is placed in a standard string literal:
    ```csharp
    sb.AppendLine($"    [Fact(DisplayName = @\"{fileName} :: {escapedDisplayName}\")]");
    ```
    If the `.ino` file itself contains a double quote in its file name (which is technically possible in some Unix filesystems, although invalid on Windows and highly non-standard), this could theoreticaly break the verbatim string. Since source files in .NET projects adhere to typical Windows/MacOS filesystem rules where quotes are prohibited, this carries practically zero risk.
