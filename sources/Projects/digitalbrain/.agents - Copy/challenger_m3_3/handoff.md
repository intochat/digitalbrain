## 2. Logic Chain

- **A. Special Character Escaping Verification**:
  - Valid InoLang scenario names can contain literal backslashes `\` and tabs `\t`.
  - In our updated `GeneratorStressTester` (*Scenario D*), we generated test facts for scenario names containing backslashes, double backslashes, tabs, and trailing backslashes.
  - The generated code uses verbatim string literals (`@""`) which treat backslashes and tabs literally, preventing compile-time `CS1009` errors.
  - Verified that the generated code parsed successfully using the Roslyn syntax trees with 0 syntax errors, and the output matched exactly.
- **B. Invalid Quotes & Syntax Error Interception**:
  - InoLang string parsing (`Lexer.cs` lines 141-155) does not support escape characters in string literals. Double quotes `"` inside a scenario name are treated as delimiters, terminating the string literal and causing lexing/parsing errors.
  - The generator handles these parsing errors by catching `bag.HasErrors` cleanly and outputting a `Scenario_CompileError()` fallback test fact.
  - Verified (*Scenario E*) that invalid quotes inside scenario names do not crash the source generator and successfully fallback to `<compile error>` representation.
- **C. Duplicate Scenario Name Suffixing**:
  - Multiple scenarios with the identical name will collide if generated with identical DisplayNames.
  - In `InoTestGenerator.cs` lines 168-181, the generator calculates the duplicates using `GroupBy` and aggregates them into a `duplicateNames` set. Suffixes ` [#{i}]` are successfully appended to the DisplayNames of these duplicate scenarios.
  - Verified (*Scenario C*) that identical scenario names generated distinct, index-suffixed display names (e.g. `Duplicate Scenario Name [#0]` and `Duplicate Scenario Name [#1]`).
- **D. Zero Scenarios Verification**:
  - For files containing no scenarios, the generator intercepts this condition in `else if (doc.Scenarios.Count == 0)` and generates the `Scenario_NoScenarios()` sentinel test fact.
  - Verified (*Scenario B*) that zero scenarios successfully map to `<no scenarios>` display name without throwing exception.

---

## 3. Caveats

- **Double-Quote Escaping Limitation**: Because InoLang's lexer (`Lexer.cs`) does not support escape sequences in its string literals, a valid scenario name can never contain a double-quote `"` character under standard parsing (any double-quote will terminate the string and cause a lexer error). The double-quote doubling replacement `Replace("\"", "\"\"")` implemented in `InoTestGenerator.cs` is a safe, proactive defensive measure that ensures robustness in case the InoLang parser/lexer is upgraded in the future, or in case AST is built programmatically.
