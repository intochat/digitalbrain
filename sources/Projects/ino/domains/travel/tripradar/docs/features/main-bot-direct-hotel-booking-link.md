# Сэкономить на Booking

## Коротко
Пользователь на главной странице бота нажимает `Stays`, вводит город или название отеля, даты и получает ссылку на бронирование без лишнего шага через Booking.com.

## Flow
1. Пользователь вводит:
- город или название конкретного отеля,
- даты заезда и выезда,
- при необходимости количество гостей.
2. Бот вызывает GraphQL `hotels` и получает `properties`.
3. Бот показывает:
- название отеля,
- рейтинг,
- цену за ночь или за все проживание,
- ссылку `link` на бронирование.
4. Пользователь сразу переходит по ссылке на оплату.

## Что важно указать в ТЗ
- для MVP эта фича не требует Kafka,
- в backend есть topic `Hotels`, но бот сейчас не использует его для этого сценария,
- критично проверить, что `properties.link` ведет туда, куда нам нужно,
- если это прямая ссылка отеля, можно позиционировать фичу как обход Booking,
- если это OTA-ссылка, нельзя обещать экономию 15%.

## Формулировка для продукта
Не писать: `гарантированно на 15% дешевле`.

Писать так:
- `получить прямую ссылку на бронирование`,
- `сэкономить на комиссии Booking, если доступна прямая ссылка`,
- `показать более выгодный путь бронирования`.

## Что должен видеть пользователь
- отель,
- цена,
- ссылка на бронирование,
- короткая причина, почему это выгоднее обычного OTA-сценария.

## Scope
- WebApp пока не включаем в обязательный сценарий,
- сначала нужно проверить природу `properties.link`,
- только после этого можно обещать экономию и строить полноценную hotel value proposition.
