Here is the brainstorm, sections 1ΓÇô7 only.

#### 1. Product in one paragraph

DigitalBrain is a .NET framework for durable agents on Orleans and Aspire whose entire domain is two concepts ΓÇö **Neuron** (a durable, journaled, owner-scoped actor) and **Synapse** (an immutable typed fact) ΓÇö joined by one verb, **FireSynapse**. Modules own the vocabulary at compile time; namespaces and type names are identity, not lookup. Owner prose becomes, through a Creator (AST-first Roslyn emission under a closed C# profile), exactly one reviewable `.cs` file that, after quarantine, signed owner approval, and a cold restart, runs as *ordinary* neurons on the *same* runtime, journal, and outbox as trusted code ΓÇö provenance lives in the candidate record, never in the type system. One journal is the audit spine; Flutter shell and MCP are projections that observe it.

#### 2. Core laws (max 8 bullets)

- **Two concepts, one verb.** Neuron + Synapse; FireSynapse is the only candidate-visible action. IHandle, envelope, journal, outbox, router, Creator are machinery, never a third vocabulary.
- **One journal, one turn.** Inbound receipt + state replacement + outgoing envelopes commit atomically in the owning neuron's turn; the journal is the outbox and the audit source. A second journal is forbidden ΓÇö everywhere, forever.
- **Owner and grant are runtime facts.** Authenticated ingress assigns owner; every fire is checked against a finite grant; candidate code cannot construct, read, or select envelope fields.
- **Generated code is ordinary code.** Same `Neuron` base, same activation seam, same journal as trusted modules. If generated code needs a special runtime path, the design is wrong.
- **Admission is cold and content-addressed.** Creator ΓåÆ closed-profile admission ΓåÆ quarantine ΓåÆ signed approval ΓåÆ pointer CAS ΓåÆ restart. No live type admission, no behavior registry, no interpreter.
- **Public Abstractions is the candidate-safe surface.** Anything a candidate must not touch does not live there. Control plane is a separate package by law, not convention.
- **Facts flow one way.** Broadcast facts never reply; requests are directed and reply once; reentrancy is forbidden (the DrainAsync deadlock is physics, not a bug).
- **Effects live behind trusted deep modules.** A candidate fires a contract (`AddChartPoint`); it never sees the neuron, credentials, UI, or I/O behind it.

#### 3. Package responsibilities

| Package | Responsibility | Who references | Must NOT contain |
|---|---|---|---|
| `DigitalBrain.Abstractions` | Candidate-safe vocabulary only: `Synapse`, `RequestSynapse`, `IHandle<T>`, `Neuron` base (no Orleans surface), `IDurableState<T>`, `IDigitalBrain.FireSynapse`, identity value types | Everything; the **only** core reference in generated code | Envelopes, grants, journal/outbox, capability lifecycle synapses, journal read models, control plane, any Orleans runtime type |
| `DigitalBrain.Core` | Runtime physics: `NeuronActivationGrain` (sole Orleans-facing activator), immutable route table, `SynapseEnvelope`, grant enforcement, scoped `IDigitalBrain` proxy, the **kept product** journal/outbox/turn engine, serialization wiring, payload protection, silo hosting | Kernel, module implementation projects | Aspire DSL, client edge, Creator, any new candidate-visible vocabulary |
| `DigitalBrain.Client` | Owner-scoped cluster-client facade (`ConnectAsync`), journal observation, client entry points | `DigitalBrain.Mcp`, one-file edge clients | Silo runtime, control plane |
| `DigitalBrain.Creator` | Control plane: NeuronIntent schema, Roslyn emission + fixed header, closed-profile admission, candidate records, attestation + pointer head, quiesce/two-phase cold-admit supervisor | Kernel (boot-time verify) + the creator/supervisor process | Anything a candidate can reference; runtime routing |
| `DigitalBrain.Aspire` | `AddDigitalBrain` (silo), `AddDigitalBrainClient`, service defaults (absorbs `ServiceDefaults`) | Kernel, Mcp, samples | AppHost composition DSL |
| `DigitalBrain.Aspire.Hosting` | AppHost DSL, resource names, module projections | AppHost only | Runtime anything |
| `DigitalBrain.Modules.Sdk` | Southbound MCP + webhook transports | google, salesforce module impls | Anything northbound |
| `modules/<x>/Contracts` | Domain vocabulary: synapse records + typed neuron interfaces | Module impls, clients, **candidates per grant** | Implementations, credentials, UI |
| `modules/<x>/<X>` | Trusted neurons implementing the domain | Kernel composition only | Other modules' implementations |

Six core packages, down from seven: `Security` folds into Core, `ServiceDefaults` into Aspire, `Creator` is the one addition ΓÇö and it exists precisely so control-plane types have a home that is *not* public Abstractions.

#### 5. What dies from current tree

- **`poc/` entirely, and every `DigitalBrain.Poc.*` package.** Candidate activation, envelope, grants land in Core; Creator and control plane land in `DigitalBrain.Creator`; the chart proof re-homes as the first vertical. No Prototypes means no parallel runtime survives.
- **`DigitalBrain.Scripting`** ΓÇö the dummy generate+run process is superseded by the Creator.
- **`DigitalBrain.Security` and `DigitalBrain.ServiceDefaults` as packages** ΓÇö folded per ┬º3.
- **`src/core/{kernel,aspire,security}` grouping folders** ΓÇö flat.
- **From Abstractions:** `Capability*` lifecycle synapses, `JournalRead/Tally/Snapshot`, `IJournalObserver`, `ClientEntryPointAttribute`, `NeuronCallTimeouts`, `SettledDeliveryFailureAttribute`, `ProtectedPayloadReference` ΓÇö all relocate to Core or Client. Residual `BehaviorId` wire-compat identity types ΓÇö deleted outright.
- **`BroadcastCatalog`/`BroadcastSubscribers`** as a subscription mechanism ΓÇö subsumed by the immutable route table (trusted modules get their bindings compiled at catalog build; candidates get theirs at cold admit).
- **`.architecture-*` scratch files**, and CORE-DESIGN/CORE-PLAN prose once the code exists ΓÇö code is the source of truth.

#### 6. Strongest objection + defense

**Objection:** "You're gutting Abstractions and rewiring routing in a *working* product to serve generated neurons ΓÇö a feature still Designed, with zero consumers today. Every module, the client, the MCP process, and the Flutter transport break at once, and grant checks tax the trusted hot path for nothing."

**Defense:** The candidate-visible surface of Abstractions is the one API this product can never change after the first approved candidate references it ΓÇö generated files are compiled third-party consumers with owner approval records attached; migrating them later means re-running Creator, quarantine, and owner approval for every family. That surface must be minimal *before* the first admit, and the merge charter's "port candidate activation" is impossible without it ΓÇö otherwise candidates transitively drag Orleans runtime, journal internals, and capability machinery, which is exactly the "control-plane in public Abstractions" failure the hard rules forbid. The alternative ΓÇö a second candidate-facing vocabulary beside the product one ΓÇö is the dual-journal mistake expressed in types, and the POC already proved where that ends. The cost is bounded: types move packages, namespaces stay, the compiler enforces completeness, and the root gate proves it. The hot path is untouched: grants attach to route bindings at catalog build / cold admit, not per fire ΓÇö a trusted module's fire resolves the same pre-computed binding it does today; only envelopes entering generated code carry pinned revisions.

#### 7. Minimal first vertical

Re-run the POC hypothesis **on the merged runtime** ΓÇö that single act retires `poc/` and proves the merge:

1. **Carve `DigitalBrain.Abstractions`** down to the candidate-safe surface; relocate everything else; root gate green. The compiler is the migration oracle.
2. **Port into Core:** `NeuronActivationGrain` + route table + `SynapseEnvelope` + grants, *over* the existing product turn/outbox ΓÇö never beside it. Proof: the existing chat module runs unmodified through the new seam.
3. **Creator emits one candidate** ΓÇö `ElonPostRuleNeuron` + `ElonPostMatched` + `ChartForwarderNeuron` in one file, fixed header, closed profile, quarantine, signed approval.
4. **Cold admit:** quiesce ΓåÆ drain ΓåÆ child verifies ΓåÆ pointer CAS ΓåÆ swap.
5. **Live proof, journal-read:** fire `SocialPostObserved` through authenticated ingress (test fixture in samples, not a shipped module); `AddChartPoint` lands in the chart neuron (chart contract + neuron live in the shell module ΓÇö a chart is a scene surface, not a new package); one correlation chain in one journal; kill the process with an undelivered outbox envelope, restart, exactly one point on the Flutter chart; an ungranted contract is refused at admission.

That vertical exercises every ported piece ΓÇö activation, grants, Creator, cold admit ΓÇö against every kept piece ΓÇö turn, outbox, journal, shell ΓÇö and nothing it needs is speculative.
