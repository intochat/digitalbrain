# Flutter local persistence audit — 2026-09-28

Scope: source-only audit of `src/Modules/Google/Flutter/app` (shell, core, UI, web); no actual user preferences, credentials, browser databases, or files were read. Backend source was consulted only to identify existing neuron owners. This document proposes migration boundaries, not implementation.

## Main finding

The shell still has a durable, device-local workspace database. `shell/lib/workspace/workspace_store.dart:15–22` implements `WorkspacePersistence` using `SharedPreferencesAsync.getString/setString`. `WorkspaceStore.toJson/save` (`:508–533`) serializes the entire aggregate into one JSON preference on every save. It is not merely a cache: it contains unsent drafts, project/conversation discovery, settings, local artifacts and retry operations unavailable from the current remote workspace snapshot.

Production scoping is `intocaht.workspace.v1.<base64url(origin|workspaceIdentity)>` (`shell/lib/main.dart:58–68`); `workspaceIdentity` becomes `principalId|accountId` in `core/lib/src/ui_client.dart:90–91`. Also account for the constructor's legacy unscoped `intocaht.workspace.v1` key (`workspace_store.dart:16`) and offline scope. The key's `intocaht` spelling is intentional existing source behavior. Browser/native physical storage is delegated to the plugin; no app-owned IndexedDB implementation or separate direct durable filesystem writer was found in the audited Flutter application sources.

## Remote ownership currently stops short

`WorkspaceRemoteController` (`shell/lib/workspace/workspace_remote_controller.dart:5–68`) correctly treats revision events as invalidations and reloads authoritative snapshots. However `WorkspaceSnapshot` (`core/lib/src/models/workspace_models.dart:26–53`) contains only revision, windows and first-run metadata. It cannot reconstruct the complete local aggregate.

`WorkspaceStore.reconcileWorkspace` (`:342–429`) updates remote window references, adds image documents inferred from neuron IDs, reconciles open membership, and then persists the aggregate locally. It retains artifact payloads and local state. Startup deliberately suppresses server-open windows (`:348–365`); `load` also clears open/minimized/active/collapsed state (`:481–487`). Migration must explicitly preserve or revise this startup behavior, rather than assuming the stored presentation is fully restored today.

`workspace_app.dart:81–136` starts controllers only for projects already in the local list. Thus removing preferences alone would hide non-default projects and conversation thread discovery. Backend workspace enumeration must precede the remote subscriptions.

Server conversation restore (`workspace_chat.dart:102–161`) requires the locally known thread ID and merges canonical turns into local message entries. Existing `src/Modules/AI/AI/Agents/AgentNeuron.cs:234–316` owns server conversation state, but it does not replace the frontend conversation index/drafts. Import messages by stable run/message IDs; do not blindly append a second transcript.

## Bytes, temporary files, credentials, and exports

* Artifact `data` is an unrestricted map serialized wholesale. `workspace_chat.dart:296–321` recognizes `data:image/` strings and omits them only from agent context; that does not strip them from persistence. Historical inline binaries must be detected during import, uploaded to an asset owner backed by Blob, and replaced with stable asset references. No dedicated Flutter durable binary file store was found. `ui_gallery_preview.dart:354` contains a compiled static PNG fixture, not user data.
* Image source/rendered PNG bytes are memory (`app_surface_host.dart:34–35,118–128,276–306`). Save calls server `prepare-save`/`saveImageCopy`; the Files/Downloads UI here is a server app listing (`:78–94`), not an OS download API. Backend Downloads storage requires the backend audit. No separate app-owned download writer was found in Flutter.
* Native voice capture uses `getTemporaryDirectory` and recording paths (`workspace_voice.dart:129–141`), reads through `voice_file_io.dart:3`, and attempts deletion on stop/failure/dispose (`workspace_voice.dart:66,119,175`; `voice_file_io.dart:8–14`). Web recording returns a blob URL fetched into memory (`voice_file_web.dart:3–14`); its cleanup hook is a no-op. These are capture scratch resources, not durable application records. The resulting text draft is durable and belongs in conversation state. Do not bulk-migrate abandoned microphone temp files.
* Web username/password live in sessionStorage (`auth/credential_store_web.dart:6–28`). Native credential persistence is intentionally a no-op (`credential_store_io.dart:3–10`). Browser HTTP uses browser-managed HttpOnly cookies (`core/lib/src/session_http_client_web.dart:4–6`); native CookieHttpClient stores cookies in an in-memory map (`cookie_http_client.dart:12`). These are transport/session secrets, not workspace content. Do not import raw passwords or session cookies into generic neuron snapshots. Browser sessions necessarily retain an authentication token/cookie even after durable application content moves server-side.
* Server-controlled developer mode is deliberately excluded from local serialization (`workspace_store.dart:330–338`); keep it server-authoritative.

## Migration requirements

1. Define complete neuron schemas and server enumeration/read/mutation APIs for the missing project catalog, conversation metadata/drafts, preferences, presentation, artifact references, and pending operations before removing local writes. Use the configured Orleans grain storage provider backed by Azurite Blob; Flutter should not receive Blob credentials or write storage blobs directly.
2. Import from the authenticated client that can access its own preferences. Preserve existing IDs and validate current principal/account ownership against the server; an origin/account-derived preference key is a routing hint, not authorization. Handle legacy/unscoped/offline keys separately so old data cannot silently enter the wrong account.
3. Read raw JSON before the existing `load()` normalization clears presentation fields or prunes attachment references. Validate version and each record, keep undecodable records recoverable, and inventory inline binaries without logging their contents.
4. Use an idempotent import manifest keyed by principal/account, source scope and content hash. Persist checkpoints and ID/reference mappings server-side; upload assets before committing references. Preserve pending operation IDs and expected revisions; query/reconcile already-completed image operations before replay.
5. Resolve duplicates by typed owner and revision. A local table copy must not overwrite a newer canonical table; an unsent draft must not be discarded as a cache. Preserve unresolved local-only work as an explicit imported draft/conflict record. Reconcile local messages against server turns by run IDs.
6. Switch reads and writes to neuron-backed APIs only after verified server read-back of all imported records. Keep the old preference snapshot until acknowledgment; remove it only after a successful import and recovery policy. A malformed local load currently reports an error but later `save()` can still overwrite the original preference (`workspace_store.dart:500–528`), so migration needs a stronger overwrite guard.
7. Replace unconditional whole-aggregate saves with explicit commands/revisions. Keep only in-memory projections, scratch recordings and session auth locally; do not keep a durable offline mutation queue if the requirement is literally all durable application data in neurons. Unsaved/offline status must be visible rather than claiming server persistence.

Verification targets: fresh browser/device reconstructs every workspace and conversation; account switching never imports another scope; offline/legacy snapshots import without ID loss; interrupted import retries without duplication; image edit/save retries retain operation identity; asset references resolve; server-newer revisions win without losing drafts; clearing local application storage after migration does not lose durable work.
