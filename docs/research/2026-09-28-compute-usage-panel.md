# Compute usage panel: source review and recommendation

Research date: 2026-09-28. Proposal only; no product changes in this note. Sources are the repository's own contracts and implementation.

## Recommendation

Make the bottom **Compute** label an actual button. Open a compact panel anchored above it on desktop and a sheet on narrow screens. Keep it outside the workspace window/dock lifecycle, preserving the clean start experience. Show an account allowance summary and an explicitly scoped **This workspace** activity list, newest first. Each activity expands into consumed resources: model/provider and reported token categories, app/tool operations, and data sources/rows read when available. Separate **Preview · not charged**, **Reserved**, and **Charged** values; never add previews to charged totals. Start with a recent period plus “Load more.”

Reuse and minimally generalize the existing **collection neuron** for the list presentation. Keep financial facts in a separate typed usage query/projection backed by existing domain stores. A new list neuron would duplicate an existing UI primitive; using the existing collection as a billing ledger would give presentation state the wrong responsibility.

## Data and implementation shape

1. **Add a read-only usage projection**, with stable activity/intent IDs, timestamps, scope, outcome, resource entries, separate preview/charged/reserved amounts, price-book version, and a next cursor. This is proposed API work, not an existing endpoint. Keep amounts authoritative on the server. Account authorization and workspace membership must be enforced there.
2. **Compose existing sources carefully.** `IIntentUsage` durably retains per-intent provider/model, timestamp and nullable token categories; null explicitly means unreported, not zero. Meter events retain workspace/intent/app, unit and quantity. `IWallet` supplies account charges and platform costs as different ledger kinds. Do not present platform cost as the user's charge. [Token usage](../../src/Modules/AI/DigitalBrain.Modules.AI.Contracts/Metering/IntentUsage.cs), [usage persistence](../../src/Modules/AI/DigitalBrain.Modules.AI/Metering/IntentUsageNeuron.cs), [meter contract](../../src/Modules/DigitalBrain/Compute/DigitalBrain.Modules.Compute.Contracts/Metering.cs), [wallet contract](../../src/Modules/DigitalBrain/Compute/DigitalBrain.Modules.Compute.Contracts/Ledger.cs).
3. **Add scoped, paged queries rather than loading every record.** The current meter-store read is global/unpaged; the wallet read is account-scoped/unpaged. Ledger entries lack workspace IDs, while token usage is keyed by intent without a browsing index. Reliable workspace filtering therefore needs an authorized intent-to-workspace association or projection; do not guess from account totals. Tool-call/touched-data receipt summaries also need durable indexing if they should survive beyond available conversation history. [Meter store](../../src/Modules/DigitalBrain/Compute/DigitalBrain.Modules.Compute/Metering/PostgresMeterStore.cs), [wallet](../../src/Modules/DigitalBrain/Compute/DigitalBrain.Modules.Compute/Ledger/WalletNeuron.cs), [activity collection](../../src/Applications/IntoChat/IntoChat/Agent/AgentReceipts.cs).
4. **Extend collection presentation minimally:** neutral empty/error states, render secondary text, optional trailing amount/status, optional read-only selection mode, and an explicit page action. Preserve file-browser behavior for existing consumers. Bind bounded pages of the usage projection to it; row activation opens resource details in the same panel.
5. **Move passive receipt presentation out of chat**, including the separate `charge-receipt` UI-card path. Keep interactive consent/approval and plan cards in chat. Retain old receipt records for migration/history; filter them from visible messages after the panel can display them. [Both receipt rendering paths](../../src/Modules/Google/Flutter/app/shell/lib/workspace/workspace_chat_presentation.dart).
6. **Refresh from authoritative state on open and after activity finishes.** Handle receipts arriving after `RUN_FINISHED`; deduplicate by stable IDs and invalidate/refetch the first page. Add server change signals only where needed; existing `CollectionChanged` signals concern UI state and do not constitute a financial usage subscription. Include loading, empty, retry, partial/unreported usage and stale states. Reopen must recover history without relying on a live chat stream.

## Suggested first delivery

One Compute panel with explicit account allowance heading, workspace activity filter, expandable rows, and paged history; remove passive chat receipts only once equivalent information is available there. Keep the existing limits indicator, but label reservations clearly. Test account/workspace isolation, cursor ordering/deduplication, preview versus charge totals, missing usage, late receipts, reload recovery, and narrow layouts. No external framework documentation is needed to establish these repository-specific findings.
