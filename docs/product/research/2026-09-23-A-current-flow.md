# A-current-flow

## Summary
How IntoChat works today, told as the path of one request. The user types "Show me all customers" in the Flutter workspace chat. The client sends POST /agent with a single user message (core/lib/src/ui_client.dart:422-460). The specialist the user picked is not included in that request. The IntoChat host (Agent/AgentEndpoints.cs:19) turns the owner and workspace into a hashed workspace scope, opens an SSE stream and hands off to ConversationCoordinator. The coordinator does not use the AI module's AgentNeuron. It runs AgentTurnRunner inside the HTTP process against a separate IConversation grain, with one hard-coded instruction string and the same 16 tools on every turn: supabase_schema, show_supabase_query_table and 14 code/behavior tools (ConversationCoordinator.cs:46-48). The model reads the schema straight from the Supabase provider, then calls show_supabase_query_table(title, sql). That call is handled by QueryWindowOperation: a journal grain, then ISupabaseTable.CreateFromQueryOnce (SQL guard, a LIMIT 0 describe, a check for 1-32 columns), then IWorkspace.Open with up to 8 retries. The model only gets back a window id; it never sees the rows. The Flutter client picks up the workspace revision over SSE and reads GET /workspaces/{id}/tables/{tableId}?offset&limit=25. Every page runs a fresh query plus a count(*) against Supabase. Filtering and sorting are done by the user in the UI, since the assistant has no tool for them. This path works, and a scripted-model E2E test covers it; the last commit was "Fix customers".

Outside that one path, most of what is in the product is unused or broken. The IntoChat project removes 14 source files (26 routes) from compilation; they refer to a namespace that no longer exists. The Flutter shell still calls those routes: voice transcription, workspace artifacts, /ui/tables, the live brain graph and /programs. So all six items in the "New work" menu are enabled but go to routes that don't exist. The live Aspire traces show /chats/main/brain/events returning 404 every 2 seconds. A test widget (InboxBanner) polls six demo widgets named "e2e" every 2 seconds, and each Orleans call shows up as duplicated client/server spans. That is where most of the trace noise comes from. There are three table neurons, two agent runtimes plus an unused legacy one with a roughly 100-line prompt naming about 45 tools that mostly don't exist, three ways to expose behavior tools, two ways to host behaviors, and two persistence models (grain storage and local-disk JSON). Several modules run in the AppHost but can't be reached from the product: ClickHouse with its seeded leads data, Memory/Qdrant, the Salesforce hosted MCP, and a fake Twitter module with an ElonBitcoin demo behavior. The specialist picker (Salesforce Admin, Lead Researcher, Automation Builder) changes nothing on the server.

The failed "card with date of birth" request has a clear cause. The assistant has no tool that draws UI, so any UI request becomes a 9-step C# authoring pipeline: draft, compile and test in a contained Windows process, then deploy. The contract catalog the model reads is a list of reflection-generated signature strings. `ITextField.Configure(string label, string kind)` does not say which kinds are allowed, and TextFieldNeuron rejects anything outside {text, number, password, suggest} only at runtime, so "date" passes compile and tests and then fails once deployed. Even a successful deployment has no supported way to show up in the user's workspace, because behaviors don't receive the workspace scope. The same weak typing affects secrets: a "password" field value is stored in grain state and sent out in a TextFieldChanged signal, and the Flutter renderer only masks kind == 'secret', which the server rejects.

The documentation adds to the confusion. CONTEXT.md, the glossary a newcomer reads first, describes Synapses, Journals, Entities, IHandle<T>, SubscribeTo, a script-saving IBehavior and specialist IAgent modules. None of these exist in compiled code. The kernel is actually small: Neuron = an Orleans grain with observers, Signal = an empty record delivered live, IDigitalBrain = Get<T> + SubscribeAsync<T>. For the marketplace, Compute and SDK-type goals this matters in three ways. There is no user identity (a single 'owner' account). Token usage is dropped by the /agent path. The assistant has no way to find neurons or modules other than code_contracts, which returns a flat list of signatures cut off at 24 KB, and the Memory module has no consumers.

### A1 (fact, high) [VERDICT: partially] End-to-end walkthrough of 'Show me all customers' (the one path that works)

Validation errors come back as {isError,message} so the model retries. 7) SSE frames TEXT_MESSAGE_*/TOOL_CALL_*; turn saved with ResultIds. 8) Client gets revision over /workspaces/{id}/events → GET /workspaces/{id} → GET /workspaces/{id}/tables/{tableId}?offset&limit=25 → ISupabaseTable.Read compiles page SQL (ORDER BY every column, LIMIT/OFFSET) + count(*) (+ total count when filtered). Filter/sort = POST .../view with expectedRevision. Grains touched: IConversation, IQueryWindowOperation, ISupabaseTable, IWorkspace (≈4 grains, ≈3 SQL statements per page).

### A10 (gap, high) [VERDICT: confirmed] The assistant can't see or refine the table it opened; every follow-up opens a new window
