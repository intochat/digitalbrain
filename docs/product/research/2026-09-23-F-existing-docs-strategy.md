# F-existing-docs-strategy

## Summary
The written material does not give one product vision. There are at least four, and the owner's marketplace is a fifth. (1) The August 2026 business strategy (E:\intochat\startup-strategy.html, in Russian) describes a personal "Jarvis". It combines context about the user (WHAT) with how experts actually do the work (HOW), and it captures the HOW as BDD Given/When/Then scenarios. Sales start with a Salesforce wedge: design partners and three processes in Q1, then a data flywheel leading to fine-tuning. (2) docs/intochat-customer-product-design.md (21 Sep, marked "proposed") describes a workspace OS with five core apps (Image Studio, Files, Tables, Notes, Automations), a shared Assistant, and a Compute ledger that reserves, then meters, then settles. (3) docs/new_programming.md is an unverified research note. It proposes "tri-modal authorship" (end user, programmer, AI) over one neuron graph, and gives an IntoChat lead generator as the example. (4) The public handbook E:\intochat\digitalbrain.docs (20 Aug) sells "a private, durable operating system" built on journaled neurons and durable Executions, and most of that machinery has since been deleted. None of these documents plans a third-party app marketplace. The one ratified runtime spec that touches it (programmable behaviors, 22 Sep) explicitly excludes a "package marketplace" and "new neuron generation". It also states that its executor is a trusted local Windows single-host process, not a sandbox.

The decisions the owner actually approved are recent and mostly concern the engine. On 2026-09-19 the owner approved a clean break. Module state is persisted, and live signals and C# behaviors restart without replay. Durable signal delivery, journals, synapses, command ledgers and graph interpreters were all removed; core runtime plus contracts shrank from 3,013 to 257 lines. Later approvals covered: code-first `WithModule` composition and the Supabase "show me data → table window" flow as the first product scenario (20 Sep); Files plus Image Editor as the first release (21 Sep); IAW-style agent neurons (22 Sep); programmable C# behaviors as a single source file plus tests, sealed into an artifact and supervised in a child process (22 Sep); the Behaviors manager UI (22 Sep); and the Roslyn/DotNet split (22 Sep). Several of the owner's new ideas would reverse these, and that should be a deliberate choice. `ValueNeuron<T> : DurableGrain` reverses the 19 Sep "no journals/replay" decision; Orleans.Journaling is still wired into the host but no neuron uses it. BDD/Reqnroll discovery reverses the deletion of every .feature file on 2026-09-17. Marketplace apps from strangers reverse the "trusted local, not a sandbox" scope.

What is built (verified by tests recorded in the ledgers):
- the typed neuron kernel (`IDigitalBrain` exposes only Get and SubscribeAsync);
- 14 composed modules;
- the agent → Supabase → workspace table journey (deterministic E2E only; the live model is unverified);
- local Files and Image Editor;
- agent/LLM neurons that record token usage but have no prices;
- the programmable-behavior pipeline;
- the Behaviors manager UI (its native lifecycle walkthrough is unfinished).

What is planned but not built: the Compute ledger and billing, durable jobs/operations, app definitions and install, the App Builder, the Form and DocumentEditor primitives, Drive, Notes, the Tables app, a secret/credential path, a structured Inbox, multi-tenant identity, and anything marketplace-related. Identity has regressed: the August docs claimed cookie identity with Owner/Admin/Builder/Viewer roles, and the code now has a single Basic-auth "owner". The owner's failed "date" field comes from the stringly-typed TextField, which accepts only the kinds text, number, password and suggest. That same field stores passwords in plain grain state, which confirms the owner's type-system and secrets pain.

The product is hard to understand partly because the documents are stale and churning. CONTEXT.md (last changed 2026-09-12) still defines Synapse, Journal, Entity, IHandle, an IBehavior neuron, Ino and WebhookNeuron, and none of these exist. README, continuation.md and several specs point to moved or deleted paths, or carry wrong status lines. The /programs WorkspacePrograms screen is dead UI whose backend routes are gone. There are 8 specs and 21 plans dated 19–22 Sep, while the earlier ratified ARCHITECTURE.md and docs/coding were deleted on 11 and 17 Sep. No single current document explains the product. Before highlevel.md is written, the plan should include a decisions register and a doc cleanup.

### F7 (gap, high) Marketplace is explicitly out of scope; the current trust model cannot run third-party apps
The programmable-behaviors spec excludes 'a package marketplace, new neuron generation, ... durable workflow engine'. It states that a child process 'is a fault/lifecycle boundary, not a security sandbox'.
