# DigitalBrain v2 — Slice 5: Connectors — Connection State Machine, Gmail/Salesforce, the Executed Rail

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development. Checkbox steps.

**Goal:** The connector template from spec v2 §4.4 as v2 kinds: a generic `connection` kind (durable OAuth state machine + closed health union + one fix action per unhealthy state), `gmail` and `salesforce` kinds (reads via provider seam; mutations ONLY as effect proposals; execution ONLY by claiming a single-use `ApprovedEffectProof`), real provider adapters ported from v1 at the HTTP level (activate when configured), and conformance coverage. Proven live via gateway/MCP: probe → `notAuthorized` with fix action `connect`; propose-send → decision on the rail → execute claims the proof and runs (fake provider in dev); execute WITHOUT approval fails closed `effect.not-approved`; second execute fails closed (single claim).

**Architecture:** One `connection` kind, per-provider instances (`connection/google-primary`). State machine folds from the journal: `notConnected → authorizing(expiresAt) → connected → reauthorizing | suspended`. Health = closed union `healthy | missingAppCredentials | notConfigured | notAuthorized | tokenExpired | providerError | networkError`, each mapping to exactly one fix action (`connect | reauthorize | retry | none`). Provider seams `IConnectionProvider` (BuildAuthorizationUrl, ExchangeCode, Probe) and per-domain seams (`IGmailProvider.ListAsync/SendAsync`, `ISalesforceProvider.QueryAsync/UpdateAsync`) — keyed DI by provider name; fakes for tests/dev, ported HTTP adapters for real use. Execution rail: `gmail.execute-send.v1` takes `{effectKey}`, grain-calls `effect.claim-proof.v1` (single-claim enforced by the effect neuron), verifies the payload digest matches the proposal it journaled, then calls the provider seam and journals the verified outcome.

**Deliberate boundaries:** No token data migration (v2 connections start `notConnected`); tokens live in journal events — acceptable ONLY while storage is volatile; **journal encryption is a hard gate before any durable storage provider** (carry). No browser OAuth dance in the live proof (no credentials in this environment); `connection.complete-auth.v1` is proven with the fake provider.

### Task 1: modules/Brain.Modules.Connections — the state machine (commit 1)

- New project (refs Brain.Contracts). `IConnectionProvider` seam: `string BuildAuthorizationUrl(string state); Task<ConnectionToken> ExchangeCodeAsync(string code, CancellationToken ct); Task<ProbeResult> ProbeAsync(ConnectionToken token, CancellationToken ct);` with `ConnectionToken(string AccessToken, string RefreshToken, DateTimeOffset ExpiresAt)`, `ProbeResult(string Health, string Detail)` where Health ∈ the closed union.
- `ConnectionKind(IServiceProvider services)`: kind `connection`; provider name = instance segment before first `-` in NeuronId tail (`connection/google-primary` → keyed service `google`). Contracts:
  - `connection.start-auth.v1` {} → provider missing from DI → health `missingAppCredentials` fail-closed error `connection.unhealthy`; else event `connection.authorizing` {authorizationUrl, expiresAt=now+10min}; output {authorizationUrl}.
  - `connection.complete-auth.v1` {code} → only valid in authorizing+unexpired (else `connection.unhealthy`); ExchangeCode via seam (provider exceptions → `provider.error`); event `connection.connected` {token…}; output {status:"connected"}.
  - `connection.probe.v1` {} → fold state: notConnected → `{"health":"notAuthorized","fix":"connect"}` event + output; connected → seam Probe (classify; tokenExpired → fix reauthorize; providerError → retry; networkError → retry); event `connection.probed`.
  - `connection.suspend.v1`/`connection.resume.v1` {reason} → events (suspended blocks probe→`{"health":"notAuthorized"}`? no — suspended is its own fold state; probe on suspended reports last health with fix none and suspended:true).
- Projection `status` (default): fold → `{state, health, fix, authorizingExpiresAt?, suspended}`.
- Tests (KernelTests, `ConnectionsKindsConfigurator` + `FakeConnectionProvider` in Sdk or test project): full happy path start→complete→probe healthy; probe before auth → notAuthorized/connect; complete after expiry → fails closed; complete without start → fails closed; unknown provider instance → missingAppCredentials path; suspend blocks resume restores. Conformance class added.

### Task 2: gmail + salesforce kinds — the executed rail (commit 2)

- Same project or sibling `Brain.Modules.Google`/`Brain.Modules.Salesforce` (choose: two thin projects, template proven). Seams `IGmailProvider { Task<string> ListAsync(ConnectionToken, int max, CancellationToken); Task<string> SendAsync(ConnectionToken, string payloadJson, CancellationToken); }`, `ISalesforceProvider { QueryAsync; UpdateAsync; }` keyed by "google"/"salesforce".
- `GmailKind`: `gmail.read.v1` {max?} → resolve connection neuron `connection/google-primary` in same space via grain read of its `status` projection; not connected → `connection.unhealthy` fail-closed; else token from... (kind cannot read another neuron's journal directly — pass through grain: add `connection.token.v1` contract? NO — simplest honest: GmailKind grain-calls the connection neuron with internal contract `connection.lease-token.v1` returning the current token, same-owner allowed). Then seam List → event `gmail.read` {count} → output messages.
  - `gmail.propose-send.v1` {to, subject, body} → KindResult.Effect (provider "gmail", payload, digest) — the kernel builds the Effect neuron (slice 1 machinery).
  - `gmail.execute-send.v1` {effectKey} → grain-call `effect.claim-proof.v1` on effectKey (not approved / already claimed → BrainException effect.not-approved propagates — fail closed); verify proof.PayloadDigest equals sha256 of a proposal this neuron journaled (event `gmail.send-proposed` written by propose — match digest else `input.invalid`); token via connection lease; seam Send; event `gmail.sent` {digest, providerMessageId}; output verified outcome.
- `SalesforceKind` identical template: `salesforce.read.v1`, `salesforce.propose-update.v1`, `salesforce.execute-update.v1` (connection/salesforce-primary).
- Tests: fake providers count calls; the three-step rail happy path (propose → approve via effect neuron → execute) sends exactly once; execute before approval → effect.not-approved, provider NOT called; execute twice → second fails, provider called once; digest mismatch → input.invalid; read without connection → connection.unhealthy. Conformance classes for both kinds.
