# E2E Elon-post-in-UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An Aspire e2e test boots a real Orleans cluster (Azurite in Docker), runs `ElonBitcoin` as `IBehavior`, posts a tweet through HTTP, and Playwright sees that text in Flutter **web**.

**Architecture:** Two runtimes stay split. Neuron tests keep `DigitalBrainSimulation` + in-process memory. E2E uses `E2EDigitalBrain.StartAsync<TAppHost>` only — AppHost graph, Azure Storage emulator, real silo, Flutter `web-server`. `IBehavior` stays a client loop on `IDigitalBrain` (`On<Posted>` → `Notify`). UI is a **production notification neuron** the Flutter shell already can render, not the test `INotification` grain. Flutter host kind is one options type (`FlutterHostOptions` / `DigitalBrain:Flutter:Hosting`) bound from AppHost run and from e2e args.

**Tech Stack:** Orleans 10, Aspire 13.5 `DistributedApplicationTestingBuilder`, Azurite (`AddAzureStorage().RunAsEmulator()`), Flutter `web-server` on `54723`, Playwright .NET, xunit v3.

**Out of scope:** Time Aspire.Hosting / Time e2e. Runtime codegen of behaviors. Real Twitter API. Windowed Flutter in CI.

---

## Why it does not work today

1. **AppHost cannot compile on this branch.** Flutter, Excel, Memory, AI, IntoChat still `using DigitalBrain.Abstractions.*`. Kernel is `DigitalBrain.Contracts` + `Neuron`/`PublishAsync`. Until those modules compile, `E2EDigitalBrain.StartAsync<Projects.IntoChat_AppHost>` is dead.
2. **Elon UI is a test grain.** `INotification` lives in `DigitalBrain.NeuronTesting`. Flutter chat is `IChat` on the old `Neuron<T>` + `ExecuteCommandAsync` stack. Nothing connects `ui.Notify(...)` to pixels.
3. **IntoChat has no `IDigitalBrain` in DI.** `AddBehavior<ElonBitcoin>()` cannot construct. Behaviors never run in the host.
4. **E2E defaults skip Flutter.** `E2EOptions.Args = ["Testing:SkipFlutterHost=true"]`. Correct for health-only; wrong for UI.
5. **Full IntoChat graph is too fat for a first e2e.** Qdrant, ClickHouse, Gmail, Salesforce, Coding, Ollama are unrelated to “Elon post appears in UI.”

### Task 2: One Flutter host options object for run and e2e

`FlutterHostOptions` + `WithWindowHost` / `WithWebHost` / `WithHeadlessHost` already exist. Today AppHost hardcodes `WithWindowHost()` and e2e passes a **different** switch `Testing:SkipFlutterHost`.

- [ ] Bind host kind from configuration, not from a second boolean:

```csharp
// DigitalBrain:Flutter:Hosting:Kind = Window | Web | Headless | None
public FlutterHostKind Kind { get; set; } = FlutterHostKind.Window;
```

- [ ] AppHost:

```csharp
digitalBrain.AddModule<FlutterModule>(module =>
{
    var kind = builder.Configuration.GetValue("DigitalBrain:Flutter:Hosting:Kind", FlutterHostKind.Window);
    if (kind == FlutterHostKind.None) { return; }
    if (kind == FlutterHostKind.Web) { module.WithWebHost(); }
    else if (kind == FlutterHostKind.Headless) { module.WithHeadlessHost(); }
    else { module.WithWindowHost(); }
});
```

- [ ] Delete `Testing:SkipFlutterHost`. E2E args:

```csharp
public string[] Args { get; init; } =
[
    "DigitalBrain:Flutter:Hosting:Kind=Web",
];
```

- [ ] Local `aspire start` keeps Window (or Development default). CI/e2e uses Web (`web-server`, port `54723`, already in `ShellNames`).
- [ ] Playwright headed when `CI` is unset; headless when `CI=true`.

### Task 6: E2E test — webhook then Playwright

**Files:**
- Modify: `src/Testing/DigitalBrain.E2ETesting/E2EOptions.cs` (Flutter Kind=Web, WaitFor IntoChat + Flutter)
- Create: `src/Applications/IntoChat/Tests/ElonBitcoinUiFacts.cs`
- Package: `Microsoft.Playwright` (already in `Directory.Packages.props`)

```csharp
[Fact]
public async Task ElonBitcoinPostAppearsInFlutterWeb()
{
    var ct = TestContext.Current.CancellationToken;
    await using var app = await E2EDigitalBrain.StartAsync<Projects.IntoChat_AppHost>(new()
    {
        Args = ["DigitalBrain:Flutter:Hosting:Kind=Web"],
        WaitFor = ["IntoChat", "Flutter"],
    }, ct);

    using var kernel = app.CreateHttpClient("IntoChat");
    await kernel.PostAsJsonAsync("/twitter/webhook", new { Account = "elonmusk", Text = "Bitcoin to the moon" }, ct);

    using var playwright = await Playwright.CreateAsync();
    await using var browser = await playwright.Chromium.LaunchAsync(new()
    {
        Headless = string.Equals(Environment.GetEnvironmentVariable("CI"), "true", StringComparison.OrdinalIgnoreCase),
    });
    var page = await browser.NewPageAsync();
    var flutter = app.App.GetEndpoint("Flutter");
    await page.GotoAsync(flutter.ToString());
    await page.GetByText("Bitcoin to the moon").WaitForAsync();
}
```

- [ ] `WaitFor` includes Flutter resource name from `FlutterHostOptions.ResourceName` (`"Flutter"`).
- [ ] Health e2e can stay Kind=None or Web if cheaper.
- [ ] Run: `dotnet test src/Applications/IntoChat/Tests/IntoChat.Tests.csproj -p:CodeGraphRefresh=false`  
  Expected: Docker Azurite up, silo healthy, Chromium sees the string.

Success: this fact is the definition of “e2e fully working” for this plan.
