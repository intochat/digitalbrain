# Small observed neuron registry

Approved in chat after the Registry consolidation: delete the capability catalog, app sources, unmet intents, JSON invocation, and generated agent tools. Registry owns neuron types, vector search over types, and persistent observed instance history.

Kernel publishes `ModuleLoaded`, `NeuronActivated`, and `NeuronDeactivated` records derived from `Signal`. The existing `LocalSignalHub` delivers both ordinary neuron signals and typed silo-wide subscriptions. `ModuleInventory` retains the selected module types independently of signal delivery. The silo startup task announces selected modules. The Neuron base implements Orleans' `IGrainBase` lifecycle entry points, invokes derived virtual hooks, and publishes after successful activation and after deactivation, without requiring derived activation hooks to call base and without waiting on storage or embeddings. Activation IDs distinguish successive activations of the same neuron.

Registry discovers type metadata from the immutable selected-module inventory, preserving selected-only assembly discovery and alias validation. Vector search indexes one document per neuron type, including its description and method signatures. It requires an embedding provider and Qdrant; no keyword fallback or app capability abstraction is retained. Listing types and recording instances work without embeddings or Qdrant. Vector snapshots isolate different type sets and vector spaces.

A small Registry observer consumes each silo's live activity and forwards it to one persistent Registry neuron. Queries list types, search types, or page through observed instances with optional type/last-known-active filtering. Instance history stores first/last observation and the latest activation identity; old deactivation events cannot deactivate a newer activation. It is an observed directory, not guaranteed creation history or authoritative liveness. No durable event bus, heartbeat, or event-log retention is added. Registry excludes its own storage neuron from history to avoid waking itself to record its deactivation.

Consumers stop advertising the deleted tools and capability context. Apps retain their own manifest directory. Assistant retains explicitly registered tools; any product task which relied exclusively on arbitrary neuron invocation loses that mechanism rather than silently relocating it.

Verification: module inventory and live delivery; successful/failed activation and deactivation; normal kernel behavior without Registry; selected-only type discovery; actual vector matches, failure and composition isolation; persistent observation across registry reactivation; stale/duplicate events; paging and activity filters; affected AI/Apps/Assistant consumers; solution build. Do not rerun the previously blocked full browser E2E suite for this change.
