## Product idea (ground truth)

DigitalBrain is an open-source .NET framework for durable agents on Orleans + Aspire.

**Paradigm**
- **Neuron** — durable addressable agent
- **Synapse** — typed immutable fact (no reply)
- **Interface method / capability** — directed request that replies (trusted modules only)
- **Journal** — causal audit source (never prompts/secrets)
- Modules own vocabulary; namespaces/type names are architecture

**Vision**
A brain you program by writing ordinary C#, and that can program itself: owner-reviewed generated C# becomes ordinary durable neurons (not an interpreter, not ScriptedNeuron).

## Current state (problems)

1. **Product root** works: grain neurons, modules (Chat/AI/Shell/Memory/Google/…), Kernel HTTP, MCP, Flutter — but abstractions/core feel overgrown and residual (behavior leftovers, dual mental models, dummy DigitalBrain.Scripting).
2. **poc/** is a greenfield proof (CORE-DESIGN) of Creator → one .cs → cold-restart admit → FireSynapse-only candidates → trusted chart effect. Deliberately does NOT reference product runtime. Uses plain Neuron + NeuronActivationGrain, not grain-per-candidate.
3. **Prototypes/** is archaeology (InoLang, interpreters, old kernels) — do not design from it.

## Merge thesis (already recommended)

- Keep product Orleans turn physics (Deliver → handle → journal/outbox commit → drain).
- Port POC seams: candidate activation grain, FireSynapse-only + grants, Creator, control plane, cold admit.
- Do NOT port POC file RunStore dual journal.
- Trusted modules remain grain subclasses of Neuron with capabilities.
- Candidates are plain classes hosted by activation grain; never see GrainFactory/IServiceProvider.
