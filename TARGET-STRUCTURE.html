DigitalBrain — target tree structure

Orchestrated brainstorm: Codex gpt-5.6-terra Claude Code Grok synthesis · structure only · no trash

Product (synthesized)

DigitalBrain is a durable Orleans + Aspire brain. Owners send and observe typed facts, and can approve one reviewable C# candidate that becomes ordinary durable neurons after cold admit. Trusted modules are grain neurons with capabilities. Candidates are hosted plain neurons that only FireSynapse under grants. One journal/outbox turn physics — never dual runtime.

Core laws (locked)

  • Two concepts. Neuron + Synapse. Capabilities are trusted-only machinery, not a third domain pantheon.
  • One turn. Deliver → exact handle → journal/state/outbox commit → drain. No second store.
  • Exact handlers. IHandle<T> is exact type match — no base-type catch-all.
  • Owner is runtime-assigned. Never from source text or synapse fields.
  • Candidate surface is closed. FireSynapse + durable state only; no GrainFactory / IServiceProvider / FS / net.
  • Cold admit only (v1). Approve → signed pointer → quiesce → restart → load.
  • Effects behind trusted modules. Candidates fire contracts; trusted code owns I/O and UI.
  • Journals are causal facts only. No prompts, secrets, or arguments.

Where agents agreed / diverged

Agreed

  • Thin public Abstractions (candidate-safe)
  • Core owns turn/outbox/activation/grants/routes
  • Authoring/Creator separate — not dumped into Abstractions
  • Client = edge SDK; Aspire stays split
  • Kill dummy Scripting; do not port POC RunStore
  • Modules = domain vocabulary + trusted runtime
  • First vertical = chart/social POC path on product physics

Diverged → synthesis pick

  • One vs two Neuron bases: two fences (Candidate profile in Abs, Trusted grain in Core). Codex.
  • Kernel rename: Host (clearer). Optional mechanical rename later.
  • Creator home: src/sdk/authoring/ not under core. Codex package map.
  • RequestSynapse: out of public Abs; migrate then kill. Codex.
  • Modules.Sdk: kill package name; southbound under modules/integrations. Codex.
  • IDigitalBrain: full edge client in Client package; candidate gets internal FireSynapse proxy only.

Why two Neuron types is not dual architecture: Trusted grain Neuron holds Orleans authority (capabilities, DI, timers). Candidate Neuron is a closed ABI with FireSynapse + state only. Same domain words; different host privilege. One turn pipeline in Core owns both. Collapsing them either leaks GrainFactory into generated code or deletes capabilities.

Refactor order (structure-first)

  1. Abstractions carve — candidate-safe surface + kill public trash; solution still green
  2. Core reshape — Trusted Neuron, turns, routes, CandidateActivationGrain, grants over existing Orleans journals
  3. SDK move — Client + Aspire out of nested core; Authoring package skeleton
  4. Host — rename Kernel maps; cold bootstrap hook; chat still works
  5. Modules normalize — Vocabulary/Runtime folders; chart module for gate; southbound MCP home
  6. Authoring port — Creator + control plane from POC; delete Scripting
  7. Vertical proof — admit candidate on product host; archive poc/
